# 南康白起真相探寻

一部取材于用户提供公开资料的虚构“旧互联网档案恐怖”解密游戏。首页是虚构的“远岸社区”；访客点进一篇旧帖后，会在 437 楼回复中逐渐发现新闻目录、小组转述、贴吧记录、网友日记和匿名调查帖。

## 本地预览

```bash
python3 -m http.server 4173
```

然后访问 `http://localhost:4173/`。

## 游戏结构

- 首页只标注一句“剧情为虚构”，保留虚构的远岸社区与古早论坛外观。
- 原帖第 1—200 楼及已有日记正文不改写；后续楼层和异常回执属于游戏剧情。
- 资料入口仍位于主帖第 35、63、88、126、173、205、437 楼。
- 七道密保全部为四选一，没有默认选项；正确答案分布在不同位置。
- 第一处错误提交决定本轮坏结局。系统只说“记录已接收”，随后通过三条异常回复引用玩家选项，进入对应故事。
- 全部答对进入“留档”，不会通过最后的剧情按钮再转入坏结局。
- 七种错误结局与一种全对结局，共八份可收集回执。结局不再由最后的独立判断菜单决定。
- 标题补全也改为下拉选择；结局互动是点选回复、处理记录，不要求输入数字或文字。跳转楼层的输入框只是导航。
- 回复按玩家点击逐条读取；暗场由玩家选择退出账号触发。没有鬼图、突然放大的脸或闪屏。
- 回执会记录错误题号与提交内容。重试从本次错题开始，保留此前正确答案和收集；全对后重试从第一题开始。
- 使用 `yuanan-forum-mystery-v7` 保存新规则进度。旧 v6 存档不删除，但不混入新的错题结局收集；首次进入沿用旧静音偏好。
- 本地保存答题、回复阅读位置、结局阅读位置、发帖草稿和静音偏好。所有剧情中的发帖、申诉和删除均不调用真实站外服务。

## 结局路线（剧透）

一旦答错，本轮不再继续答后面的题，进入该题对应的剧情。每题三个错误选项都进入该题的同一类结局，接收回执会引用玩家实际选过的内容。

| 首次出错位置 | 对应结局 | 核心异常 |
| --- | --- | --- |
| 第 1 题：关系 | 熟人 | 系统为“认识他的人”补写一整段过去，最终接替身份 |
| 第 2 题：日数 | 空出来的那一天 | 玩家被放入算错的时间里，回复落在过去 |
| 第 3 题：来源 | 没有来源的人 | 文字得以保存，发言者从记录里消失 |
| 第 4 题：日期顺序 | 先注销的人 | 退出发生在进入之前，当前操作被当作离线缓存 |
| 第 5 题：日记 | 日记的作者 | 空白标题接受玩家署名，日记开始书写阅读者 |
| 第 6 题：楼层 | 第1900楼 | 当前访问变成旧帖证据，更正继续成为下一楼 |
| 第 7 题：登录者 | 下一位 | 不被计入的访问者留下警告，又成为下一轮的开端 |
| 七题全部正确 | 留档 | 保留原始记录与缺失，不替空白填写身份 |

正确答案：只听过名字、了解一点的网友 → 18 天 → 原账号、原帖日期、楼层与链接 → 05月07日 / 05月19日 / 06月15日 → 《那个人》 → 第1894楼 → 后来拿泄露凭据验证传闻的人。

题库和判定函数：`game-rules.js`。自动测试覆盖所有 28 个可选答案、非法输入和八种结果：

```bash
node --test tests/rules.test.cjs
```

## 发布与撤销

GitHub Pages 从 `main` 分支仓库根目录发布。修改后提交并推送到现有仓库，等待 Pages 部署完成。仓库 Settings → Pages → Build and deployment → Branch 选择 None 并保存，可停止发布而保留代码。需要恢复旧版时，通过 `git revert` 撤销对应提交后推送，避免强制覆盖历史。
